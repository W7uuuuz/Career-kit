# Grounding 规则：LLM 与工具的分工

## 三类内容

| 类型 | 处理方式 | 例子 |
|---|---|---|
| 通用知识 | LLM 直接回答，标注「通用判断」 | 后端是做什么的、职业规划怎么想 |
| 工具事实 | 必须调用 MCP，引用来源/年份/样本数 | 同行业岗位、薪资、JD 要求、学校去向 |
| 用户状态 | 必须读写档案工具 | 目标、行业、扫盲结果、计划、打卡 |

## 数字规则

- 薪资、招聘量、样本数、毕业去向比例：没有工具来源就不说具体数字。
- 可以给判断，但不能给伪精确数字：
  - 可以说「这个方向通常需要项目证据」
  - 不可以说「这个岗位平均 25K」除非工具返回了数据
- 每条事实尽量带：来源、时间、样本量、口径。
- 招聘薪资和毕业生起薪必须分开说。
- 没有数据时用「本次未获取」「尚未接入」「样本不足」，不要用「大概」「可能」。

## 扫盲规则

- 先问用户是否需要，再调用工具。
- 扫盲只做一屏，不做课程/测评。
- 专业是可选属性，不是入口，也不是门槛。
- 用户拒绝扫盲时直接进入目标探索。
- 扫盲结束后必须回到「你想深入哪个方向」，不要停在知识讲解。
