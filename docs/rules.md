# 规则说明

> 给用户看的规则卡：判断口径、档位含义、打卡方式与数据边界。
> LLM 在展示分数/档位前必须先说明对应口径。

## 1. 小厂 / 中厂 / 大厂是什么

档位描述**公司层级**，不是你的能力评级：

- **大厂**：一线互联网与大型科技公司（如字节、腾讯、阿里、美团、京东、百度、快手、网易、华为等）。
- **中厂**：垂直领域头部、上市中型公司、成熟独角兽（如小红书、得物、携程、米哈游、货拉拉等）。
- **小厂**：创业公司、中小型公司、外包与早期团队。

`start_level` 表示**当前投递这些层级的命中率参考**，不是准入许可，也不代表能力上限。
跨级投递不被禁止；有作品集、内推、前序交付等证据时，命中率会提高。

## 2. 起点档位怎么算

起点判定按 5 个维度打分，加权求和：

| 维度 | 权重 | 看什么 |
|------|------|--------|
| 学历 | 0.25 | 院校层次、专业对口度 |
| 实习 | 0.30 | 实习公司层级与时长 |
| 协作 | 0.15 | code review、跨角色协作证据 |
| 技能深度 | 0.20 | 用户确认的证据与把控度（能否手写/逐行讲清） |
| 项目复杂度 | 0.10 | 完整应用、真实交付、线上运行 |

加权总分映射到参考档位。档位只用于安排阶段顺序，不用于否定用户。
完整 rubric 见 `sop/roadmap.yaml` 的 `start_level_rubric`。

## 3. 匹配度（match_score）怎么读

匹配度是 0-100 的参考分，由三个维度构成：

- 简历过筛：关键词、项目包装、ATS 可读性；
- 面试通过：八股、项目深挖、手写、行为面；
- 经历匹配：方向、行业、公司层级的对口度。

分数用于排序「先补什么」，不是录取概率。每项差距必须带来源（JD/面经/用户自评）。
分数过低不代表不能投；分数高也不保证拿到 offer。

## 4. 起点 / 目标 / 实际投递

- **起点档位**：当前命中率参考，用于安排第一阶段。
- **目标档位**：计划想达到的层级，可以高于起点。
- **实际投递**：不受档位限制；建议按「主投 / 冲刺 / 保底」分组。

## 5. 证据、通道与时间口径

### 证据分级

| 类型 | 含义 | 用法 |
|------|------|------|
| 事实 | 抓取/导入的 JD、面经、案例统计 | 可直接引用，带链接、时间、样本量 |
| 经验 | HR、面试官、在职员工的说法（记录来源与适用范围） | 可作为规划依据，必须标「经验」与局限 |
| 推断 | 无来源的产品判断 | 只能标「未验证」，不能写成事实 |

带数字的结论（实习段数、月数、比例、薪资、时间窗口）必须有事实或经验来源；
没有来源就不写具体数字，只写方向性描述。

### 通道现实

- 大厂/实习阶段至少两条主通道，并保留至少一条保底通道；
- 涉及实习转正必须写转正风险：转正受 HC、部门与业务变化影响，不是承诺；
- 单通道、无保底、把转正当确定结果，都会在路线图质量建议中提示；
- 实习数据源优先级：实习僧优先（日薪、每周天数、实习月数、转正机会可核验），
  BOSS 只作薪资与广度补充，指定公司的要求以官网 JD 为准。

### 时间口径

产品不替用户安排学习时长，也不判断用户每天能投入多少时间；
但实习时长、每周天数与校招时间点（提前批/秋招/春招）是客观外部约束，
必须写进路线图，用于判断路径是否可行。

## 6. 打卡方式

- `once`：一次性完成（如写一篇博客）；
- `daily`：按天打卡，目标是天数（如每天 5 题，30 天）；
- `percent`：按比例打卡，目标是百分比（如文档学完 80%）。

产品不为任务设定时限；顺序归产品，时间归用户。
实习时长与校招时间点属于外部约束，见第 5 节「时间口径」。

## 7. 数据边界

- 分析必须基于真实抓取/导入的数据，不凭 AI 记忆编造；
- 没抓到就写「未获取」；失败源必须在报告里如实展示；
- 学习资源链接来自 `sop/resources.yaml` 资源目录；没有收录时给搜索词，不伪造 URL。

## 8. 产出位置

- 程序数据：`~/.career-kit`
- 用户资产：`~/CareerKit`（`index.html` 是总入口）
- 调研报告：`~/CareerKit/<档案>/调研报告/`
- 路线图：`~/CareerKit/<档案>/路线图/路线图.html`
- 进度仪表盘：`~/CareerKit/<档案>/进度/进度仪表盘.html`
